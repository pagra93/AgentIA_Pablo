# `.impeccable.md` — Design DNA del rediseño de la guía PM x10

> Generado por aplicación manual de skills `teach-impeccable`, `audit`, `critique` y `frontend-design` sobre `pm-agent-system-guia-de-uso.html` (versión actual: 2542 líneas, 14 pestañas).

---

## 1. Design Context (teach-impeccable)

### Users
- **Pablo**, fundador-operador. Usa la guía día a día como cheatsheet: "estoy haciendo X → ¿qué comando uso?"
- **Futuros colaboradores** (cuando lleguen Marketing/RRHH) — usarán la guía como onboarding al sistema PM x10
- **Yo (Claude Code)**, cuando el usuario me pide "lee la guía y dime cómo hacer Y"

### Job to be done
"Quiero encontrar en <30 segundos qué comando usar para mi situación actual, sin tener que leer teoría."

### Brand Personality
**3 palabras**: preciso · referencial · sin ruido.

**Voice**: técnica pero amable. Como la doc de Stripe o Linear. Frases cortas. Verbos directos.

**Anti-references**: hacker dashboards, "cyber UI", developer cosplay con monospace por todas partes, dark mode con neón.

### Aesthetic Direction
**Editorial técnica**, no "cyber". Inspiración: Linear docs, Stripe docs, Pirsch dashboards, Lobsters.

- **Theme**: dark con tinte cálido (no `#000`, no azul puro). Permitir light mode futuro.
- **Tipografía**: protagonista. DM Sans en cuerpo, **eliminar DM Mono como decoración** (solo en código real).
- **Color**: 1 accent + 3 semánticos máximo (success/warning/danger). Quitar la paleta de 9 colores actual.
- **Density**: alta pero respiratoria. Whitespace como herramienta, no leftover.
- **Composición**: asimétrica. Tipografía + espacio crean jerarquía, no border-lefts coloreados.

### Design Principles (que guían todas las decisiones)

1. **Tipografía manda, no decoración.** Jerarquía por tamaño/peso, no por colorines o bordes.
2. **Una cosa a la vez.** Cada página/tab tiene un job principal. Si compite, lo movemos.
3. **Recorta hasta que duela, después un poco más.** 50% menos contenido = 100% más usable.
4. **Anchor over scroll.** Sub-nav lateral persistente para tabs largas. Nunca scroll ciego.
5. **Touch antes que pixel.** 44px de target mínimo, focus visible, semantic HTML.

## 2. Audit Report (HTML actual — baseline)

### Anti-Patterns Verdict

**¿Look AI-generated? — SÍ.** Brutalmente honesto: este HTML tiene **7 tells clásicos de AI slop**.

| Tell del skill `frontend-design` | Evidencia en el HTML actual |
|---|---|
| Dark mode con glowing accents | `:root --bg #0b0b14` + 9 accents brillantes (red, blue, cyan, pink, yellow, etc.) |
| AI color palette (cyan-on-dark, neón) | `--blue: #45aaf2`, `--cyan: #2b6777`, `--pink: #e056a0` sobre `#0b0b14` |
| Monospace como decoración técnica | `DM Mono` en headers, badges, contadores, footer — "lazy developer vibes" |
| Identical card grids (icon + heading + text repetidos) | `.folder-card` repetido 50+ veces con misma estructura |
| Rounded rectangles con border-left coloreado | `.folder-card.red`, `.folder-card.orange`, etc. — 9 variantes de "lazy accent" |
| Hero metric layout | `.header-stats` con "18 agentes \| 17 commands \| ..." — patrón AI-typical |
| Center everything / no asymmetry | Tabs centradas, content max-width 960px centrado, sin composición intencional |

### Executive Summary

- **Total issues encontrados**: 23 (5 critical, 8 high, 7 medium, 3 low)
- **Most critical**: AI slop verdict (FAIL), 14 tabs (cognitive overload), contraste WCAG fail (`--text4` sobre dark = 2.6:1)
- **Overall quality score**: 4/10 — funcional pero inefectivo para uso diario
- **Recommended next steps**: rediseño visual + restructura (no es suficiente reorganizar)

### Detailed Findings

#### Critical (5)

**C1. AI slop visual — FAIL** · *frontend-design anti-patterns*
- Location: `:root` + clases `.folder-card.[color]`
- Impact: el interface se siente AI-generated. Pablo lo reporta como "muy difícil para el día a día". El visual actual no comunica "guía técnica de referencia", comunica "hacker dashboard".
- Recommendation: rediseñar paleta a 1 accent + 3 semánticos. Eliminar DM Mono como decoración.
- Suggested command: `frontend-design`

**C2. 14 pestañas = cognitive overload** · *information architecture*
- Location: `.tabs` (línea 149-164)
- Impact: el usuario no sabe por dónde empezar. Tabs como `architecture`, `folders`, `workflows`, `agents` solapan; `memory` (37 líneas) tiene mismo peso visual que `scenarios` (417 líneas).
- WCAG: implícito en G134 (consistent navigation)
- Recommendation: reducir a 5 tabs por jobs-to-be-done.
- Suggested command: `distill`

**C3. Contraste WCAG AA fail** · *accessibility*
- Location: `--text3: #666` (4.2:1) y `--text4: #444` (2.6:1) sobre `--bg: #0b0b14`
- Impact: texto secundario/terciario no legible en pantallas con luz ambiente. WCAG AA requiere 4.5:1.
- Recommendation: subir text3 a `#7a7a82` (5.5:1) y eliminar text4 (replace por text3 o text2).
- Suggested command: `polish`

**C4. Touch targets sub-44px** · *accessibility / mobile*
- Location: `.tab` (padding 11px 14px = ~30px height)
- Impact: en touch devices, las tabs son difíciles de presionar. Apple HIG y Material requieren 44x44px.
- Recommendation: subir tab height a 44px mínimo.
- Suggested command: `harden`

**C5. Sin focus indicators visibles** · *accessibility / keyboard nav*
- Location: `.tab`, `.scenario-btn`, `<button>` en general
- Impact: usuarios de teclado no pueden navegar. WCAG 2.4.7 (Focus Visible) violation.
- Recommendation: añadir `:focus-visible { outline: 2px solid <accent>; outline-offset: 2px; }`.
- Suggested command: `harden`

#### High (8)

**H1. Duplicación masiva de contenido** — howmuch + scenarios + direct + tips dicen lo mismo desde 4 ángulos. Resuelto por restructura a 5 tabs.

**H2. Inconsistencia de contadores** — header dice "18 agentes" pero tab `agents` dice "Los 17 Agentes"; tab `workflows` dice "Los 15 Workflows" cuando hay 17.

**H3. Heading hierarchy rota** — `<h1>` solo en header, después `<div class="section-title">` (no semántico) sustituye `<h2>/<h3>`. Screen readers no pueden navegar la doc.

**H4. Sin landmarks semánticos** — `<header>` y `<footer>` existen pero falta `<nav>` (tabs son `<div>`), `<main>` ausente.

**H5. Tabs sin ARIA** — `<button class="tab">` sin `role="tab"`, sin `aria-selected`, sin `aria-controls`. Screen readers no entienden el patrón.

**H6. Tablas anti-pattern** — múltiples tablas con `<th>` simples sin `<thead>`/`<tbody>`, sin `scope`. Asistivos no pueden navegar columna/fila.

**H7. Card grids monótonos** — 50+ `.folder-card` en `folders`, `agents`, `workflows`. Mismo padding, misma estructura. El ojo se cansa.

**H8. `target="_blank"` sin `rel="noopener"`** — links externos a `https://impeccable.style` (si existen) sin protección. Mitigación: revisar y añadir `rel="noopener noreferrer"`.

#### Medium (7)

**M1. Inline `<style>` de 139 líneas** — funciona pero impide caching. Pasar a `<style>` externo o mantener (decisión: mantener por simplicidad, archivo único).

**M2. Hard-coded `rgba()` repetidos** — `rgba(233,69,96,0.1)`, `rgba(255,159,67,0.05)`, etc. Debería ser `color-mix(in srgb, var(--red) 10%, transparent)`.

**M3. Spacing rhythm uniforme** — todo usa 8/12/16/24px sin variación intencional. "Same spacing everywhere = layouts feel monotonous" (skill).

**M4. `.grid-3` rompe a 1 col solo a <700px** — debería ser progresivo (3→2→1).

**M5. `.intro` color text2 (#999) — borderline AAA fail** (5.8:1, AAA requires 7:1). No bloquea pero consider mejorar.

**M6. Línea de body excede 75 chars** en muchos `.intro` y `.principle-desc`. Reduce legibilidad.

**M7. `.flow-diagram` usa `<pre>` con HTML inline (`<span style=...>`) en vez de tokens semánticos** — frágil al editar.

#### Low (3)

**L1. Footer texto en `--text4` (#444)** — apenas legible, decisión de "lo escondido es lo correcto" pero AAA fail.

**L2. Badges versiones obsoletos** — `badge-green NUEVO` en componentes de hace 6 meses. Quitar.

**L3. Comentarios HTML decorativos `<!-- ═══════ X ═══════ -->`** — funcionales para navegación en código pero ruido visual al editar.

### Patterns & Systemic Issues

1. **"Folder-card como solución universal"**: cualquier información se mete en una folder-card con border-left coloreado. Esto crea homogeneidad visual y mata jerarquía.
2. **"Color para todo"**: 9 colores semánticos (`--red`, `--orange`, `--green`, `--green2`, `--blue`, `--purple`, `--cyan`, `--pink`, `--yellow`) usados decorativamente. La paleta debería ser 1 accent + 3 semánticos máximo.
3. **"Monospace decorativo"**: DM Mono en headers, badges, footer comunica "developer vibes" pero no añade información ni legibilidad.

### Positive Findings

✓ **Estructura YAML del frontmatter es buena** — fácil de parsear y mantener (CSS variables bien organizadas).
✓ **Modular type scale presente** — base font 12px con variaciones, aunque sin clamp() fluid.
✓ **Footer minimalista** — funcional sin sobrecargar.
✓ **Tabs implementadas con `data-tab` pattern** — fácil de migrar (JS reusable).

## 3. Critique Report (HTML actual — UX)

### Anti-Patterns Verdict

Mismo verdict que audit: **FAIL en AI slop test**. El interface no es memorable; podría ser cualquier doc generada por AI en 2024-2025.

### Overall Impression

**Lo que funciona**: información completa, tab por tab tiene profundidad, sin bugs evidentes.
**Lo que no**: el usuario tiene que **trabajar para encontrar lo que busca**. La guía debería responder en 3 segundos; hoy responde en 3 minutos.
**Single biggest opportunity**: convertir la guía de "manual de referencia" a "cheatsheet operativo + referencia secundaria". Default tab debe ser 80% del valor.

### What's working (3 cosas a preservar)

1. **Tab `howmuch` tiene la idea correcta** — clasificar por tamaño de tarea es el job-to-be-done real. Solo necesita reescribirse más conciso.
2. **Cards con `step-output` muestran bien el flow de comandos** — `Tu: "..."` + comandos con colores secuenciales. Útil. Mantener formato pero sin abusar de colores.
3. **Frontmatter de stories/configs documentado** — parte de tab `pm` y `wiki` es valiosa documentación. Mantener pero comprimir.

### Priority Issues

**P1. No hay un "primary action" visual** — ¿qué quieres que el usuario haga primero al abrir? Hoy: nada claro. El default tab "Que Usar" tiene 5 sub-secciones equiponderadas. Fix: header con 4-6 botones de acción rápida (los comandos más usados).

**P2. Tabs son del orden equivocado** — Setup está al final, Wiki está en posición 12 de 14. Las dos tabs MÁS USADAS deberían ser primera y segunda. Fix: nuevo orden por uso esperado (80/10/5/3/2).

**P3. "Información sin destino"** — tabs `architecture`, `folders`, `workflows` son referencia pura pero ocupan posición prominente. Fix: consolidar en una tab "Referencia" al final.

**P4. Sin sub-navegación** — tabs como `pm` (179 líneas) y `registry` (263 líneas) requieren scroll continuo. No hay anchor links. Fix: sticky sub-nav lateral con sections de la tab.

**P5. Sin búsqueda** — guía de 2542 líneas sin forma rápida de filtrar. Fix: V2 (no en este rediseño) — buscador Ctrl+K. V1 mejora con menos contenido + sub-nav.

### Minor Observations

- Header dice "Todo lo que necesitas saber" — claim excesivo. Reescribir a "Guía operativa".
- Emojis (`🏠 📚 ▶`) en estructura V3 — inconsistentes con el resto del sistema, considerar quitar.
- "Ejemplo real" repetido en cada folder-card — fórmula que se siente templated.

### Questions to Consider

- *¿Qué pasaría si la guía fuera 1 página única en vez de 5 tabs?* — descartar (pero pensarlo: la mayoría del contenido valioso es tab "Hoy"; las demás son referencia que casi nadie lee).
- *¿Necesitamos visualizar el pipeline o basta describirlo?* — el `.flow-diagram` actual es texto ASCII pre-formateado. Funciona pero podría ser más visual con tipografía variable.
- *¿Es el dark theme la elección correcta para una doc?* — cuestionable. Las docs de Stripe/Linear son light por defecto. Pero Pablo no ha pedido cambio. Dejar dark pero corregir slop tells.

## 4. Decisiones de rediseño (apply on Phase 1+)

### Cambios visuales (más profundos de lo planeado)

| Antes | Después | Justificación |
|---|---|---|
| 9 colores semánticos | 1 accent + 3 semánticos | Anti-AI-palette |
| `--red: #e94560` (accent principal) | Accent: tinte cálido neutral (TBD: ámbar tenue o terracota) | Alejar de "Mariposa" cliché AI |
| DM Mono como decoración (header, badges, footer) | DM Mono solo en código real | Anti-"developer vibes" lazy |
| `.folder-card` con border-left de color | Cards sin borde, jerarquía por typography + spacing | Anti-"lazy accent" |
| Spacing uniforme 8/12/16/24px | Escala fluida con `clamp()`: tight (4-8px) / regular (12-16px) / loose (32-48px) | Spacing rhythm |
| Tabs `<div>` con `padding: 11px 14px` | Tabs `<button role="tab">` con `min-height: 44px` | Touch + a11y |
| Sin focus-visible | `:focus-visible` en todo interactivo | WCAG 2.4.7 |
| `<div class="section-title">` | `<h2>` y `<h3>` semánticos | A11y heading hierarchy |
| Inline color rgba | `color-mix(in srgb, var(--token) X%, transparent)` | Theming consistency |
| `--text4: #444` (2.6:1) | Eliminar token, usar text3 mejorado | WCAG AA |
| Centered max-width 960px | Asymmetric layout: sub-nav lateral 240px + content fluid hasta 720px | Composición intencional |

### Cambios estructurales (del plan original, confirmados)

- 14 tabs → 5 tabs (Hoy / Capturar / Operar / Cómo Funciona / Referencia)
- Sticky sub-nav lateral en cada tab
- Header condensado con 6 quick-action buttons
- Recorte ~50% líneas

### Cambios que NO hago

- ❌ No añado light mode (no pedido, dark suficiente)
- ❌ No cambio fuentes a Inter/Open Sans (DM Sans queda, es decente)
- ❌ No animaciones decorativas (página estática)
- ❌ No buscador Ctrl+K (V2)
- ❌ No emoji en headings (descartar los `🏠 📚 ▶` legacy)
